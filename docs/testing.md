# Проверка и тестирование

## Что проверяется

Минимальный набор проверок для сдачи:

- корректный отклик на ступеньку `Iq_ref`;
- удержание `Id` около нуля;
- отсутствие роста интегратора при насыщении напряжения;
- возврат из насыщения без большого перерегулирования;
- устойчивость при `Ts = 20 us` и `Ts = 50 us`;
- корректность поведения при нулевых заданиях.

## Симуляция

В `simulation/current_loop_sim.py` используется упрощенная RL-модель электрической оси:

```text
di/dt = (u - R*i) / L
```

Это не полная модель PMSM, но ее достаточно, чтобы проверить базовую логику ПИ-регулятора, насыщение и anti-windup.

Полный запуск:

```bash
make test
```

Команда выполняет:

- `pycheck` - синтаксическая проверка Python-файлов;
- `ccheck` - компиляция C-файла с `-Wall -Wextra -Werror`;
- `pytest` - поведенческие Python-тесты ПИ-регулятора и симуляции;
- `ctest` - поведенческие C-тесты `CurrentLoop_Controller_Update()`;
- `sim` - демонстрационный прогон симуляции с сохранением CSV.

Отдельный запуск симуляции:

```bash
python3 simulation/current_loop_sim.py
```

Результат сохраняется в:

```text
simulation/current_loop_result.csv
```

## Поведенческие тесты

Python-тесты проверяют:

- ограничение значений через `clamp`;
- вычисление пропорциональной части;
- обновление интегратора без насыщения;
- заморозку интегратора при насыщении;
- размотку интегратора при ошибке в обратную сторону;
- ограничение интегратора;
- ограничение вектора напряжения;
- выход `Iq` на заданное значение в RL-симуляции;
- удержание `Id` около нуля.

C-тесты проверяют:

- обработку `NULL`-аргументов;
- отказ при некорректном `Ts`;
- отказ при некорректном лимите напряжения;
- нулевой выход при нулевой команде;
- инкремент счетчика вызовов;
- ограничение вектора напряжения;
- флаг насыщения;
- базовую работу anti-windup.

## Проверка на STM32

На железе я бы проверял:

- осциллограммы фазных токов;
- `Id`, `Iq`, `Ud`, `Uq` через UART/SWO/логирование;
- флаги насыщения;
- реакцию на ступеньки задания `Iq_ref`;
- нагрев драйвера и двигателя;
- поведение при ограничении питания и резком изменении нагрузки.

## Критерии успешности

Регулятор можно считать работоспособным, если:

- `Iq` быстро выходит на задание без устойчивых колебаний;
- `Id` не уходит далеко от нуля;
- при насыщении напряжения интегратор не продолжает расти;
- после снятия насыщения контур восстанавливается без длительного выброса;
- время выполнения функции стабильно и укладывается в бюджет прерывания.
